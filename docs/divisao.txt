DIVISAO DO GRUPO E FLUXO NO GIT
Projeto Pratico 1 - Redes (Tema 3 - Loteria)
Grupo: Nicolas, Victor e Pedro
====================================================================

Ideia geral: eu (Nicolas) subo primeiro uma base funcionando na main.
Com essa base no ar, cada um cria a sua branch, faz a sua parte sem
depender de ninguem, e depois a gente junta tudo com merge.

Dividimos por ARQUIVO e nao por "funcionalidade solta". Cada um e dono
dos seus arquivos. Assim o merge nao da conflito, porque duas pessoas
nao mexem na mesma linha.

2. ETAPA 0 - BASE NA MAIN (Nicolas, sozinho, antes de todo mundo)
--------------------------------------------------------------------

Isso aqui e o unico momento em que alguem commita direto na main.
Enquanto eu nao terminar isso, ninguem comeca (ou comeca so lendo o
protocolo.txt).

O que vai na base:

  [ ] criar o repositorio e o .gitignore (__pycache__, .venv, etc)
  [ ] subir o protocolo.txt e o divisao.txt
  [ ] comum.py:
        - constantes: HOST, PORTA (5000), INTERVALO_SORTEIO,
          INICIO_PADRAO=0, FIM_PADRAO=100, QTD_PADRAO=5
        - agora()          -> devolve a hora formatada HH:MM:SS
        - enviar_linha()   -> manda o texto ja com \n e encode utf-8
        - ler_linhas()     -> generator em cima do makefile('r'),
                              entrega uma linha por vez ja com strip
  [ ] estado.py: a classe EstadoLoteria JA IMPLEMENTADA E FUNCIONANDO
        - guarda a config (inicio, fim, qtd)
        - guarda as apostas por cliente
        - todo metodo entra e sai com o threading.Lock
        - metodos: set_inicio, set_fim, set_qtd, get_config,
          registrar_aposta, pegar_apostas_e_limpar,
          adicionar_cliente, remover_cliente
  [ ] servidor.py no minimo andando: socket, bind, listen, accept,
      manda o "HH:MM:SS: CONECTADO!!" e ecoa de volta o que chegar.
      Ja com SO_REUSEADDR ligado, senao a gente toma
      "Address already in use" toda vez que reinicia.
      Ja com a thread do sorteio sendo criada e chamando
      sorteio.loop_sorteio(estado), mesmo que a funcao ainda nao faca
      nada. Assim o Victor so precisa preencher, nao precisa mexer no
      servidor.py.
  [ ] sorteio.py com a funcao loop_sorteio(estado) vazia (so um pass)
  [ ] cliente.py minimo: conecta, thread lendo teclado, thread lendo
      socket, imprime na tela.
  [ ] README.md so com "como rodar", o Pedro melhora depois

O criterio pra dizer que a base ta pronta: subir o servidor num
terminal, o cliente no outro, digitar qualquer coisa e ver voltar.
Se isso funcionar, a base ta boa e eu aviso no grupo pra todo mundo
comecar.

--------------------------------------------------------------------
5. COMO A GENTE JUNTA (merge)
--------------------------------------------------------------------

Antes de pedir merge, TODO MUNDO faz isso pra nao empurrar conflito
pro outro:

  git checkout main
  git pull
  git checkout <minha-branch>
  git merge main
  (resolve se der conflito, testa se ainda roda)
  git push

Ordem que a gente combinou pra mergear:

  1o  Pedro   (cliente.py, nao encosta em nada de ninguem, merge limpo)
  2o  Victor  (sorteio.py, tambem isolado)
  3o  Nicolas (servidor.py, e onde tudo se encontra)

Depois do terceiro merge, todo mundo da git pull na main e a gente
senta junto pra rodar a integracao completa. Bug de integracao a
gente resolve junto, nao empurra pra um so.

Regras que valem pra todo mundo:

  - depois da base, ninguem commita direto na main. Sempre branch.
  - commit pequeno e com mensagem que explica o que fez. Nada de
    "update" ou "aaa".
  - se mudou alguma coisa do protocolo.txt, avisa no grupo NA HORA.
  - nunca commitar com o codigo quebrado na sua branch no fim do dia.
